# GLiNER2.5-Decide на фиксированной задаче обратной связи

Этот прогон сравнивает `fastino/GLiNER2.5-Decide` без дообучения с готовыми
TF-IDF, E5 и BGE-M3 из `feedback-v1`. Две задачи и три класса сохранены:
`dissatisfaction` / `correction`, каждая `no / yes / unclear`.

## Окружение

Рекомендуется отдельная Python-среда: GLiNER 2.0.0 требует `transformers<5`,
а другие эксперименты могут использовать Transformers 5. Поддерживается Python 3.11–3.13.

```text
python -m venv .venv-gliner
python -m pip install -e ".[gliner]"
```

Вторую и следующие команды запускайте интерпретатором новой среды:
`.venv-gliner/Scripts/python.exe` на Windows или `.venv-gliner/bin/python` на macOS/Linux,
либо предварительно активируйте её. CUDA-сборку PyTorch выбирайте под драйвер.
Доступны `--device cpu`, `cuda`, `mps`; фактически этот эксперимент проверен на Windows CPU/CUDA,
работоспособность GLiNER на Apple MPS данным прогоном не подтверждается.

Выполненный локальный запуск использует отдельную среду в
`artifacts/gliner25-runtime/venv`, чтобы не менять прежние зависимости.

## Запуск и перенос

Нужны сохранённые `runs/feedback-v1/data`, `labels.jsonl`, `labels-frozen.json`,
`design.json`, `evaluation.json` и `test-predictions/` от исходного исследования.
Данные не скачиваются заново и Qwen не вызывается для получения новых меток.

```text
python scripts/run_gliner_benchmark.py --download --device cpu
```

`--download` разрешает только скачивание публичных файлов закреплённой ревизии модели.
Без этого флага запуск использует локальный кеш `artifacts/hf`; в изолированный контур
нужно заранее перенести кеш и зависимости. Тексты сообщений не отправляются в Fastino,
Hugging Face или OpenAI.

Если Qwen занимает ту же GPU и используется имеющийся Docker Compose менеджер:

```text
python scripts/run_gliner_benchmark.py --device cuda --qwen-compose-dir PATH_TO_QWEN_MANAGER
```

Перед остановкой проверяются работающий сервис `qwen38-llama` и идентичность модели через API.
Сервер восстанавливается в `finally`, после чего проверяется готовность API. Параметры самого
сервера и его веса не изменяются. Файл `qwen-runtime-control.json` сохраняет необходимость
восстановления после прерывания. Повторный запуск продолжает расчёты по SQLite-журналу.

## Зафиксированный протокол

Политика `configs/gliner25-feedback.json` содержит точную ревизию модели, версию библиотеки,
описания классов, размеры окон и критерий выбора. Схемы `compact` и `rubric` заданы до просмотра
результатов GLiNER. Для длинных сообщений проверяются `max` и `mean` по logits окон.
Четыре кандидата сравниваются только на calibration; победитель фиксируется до запуска test.
Это выбор схемы на размеченной calibration-выборке, поэтому результат не является полностью
свободной от настройки оценкой zero-shot, хотя веса модели не обучались.

Для каждого окна фактическая длина проверяется процессором модели: не более 512 текстовых
subword-токенов и не более 1024 токенов вместе со схемой. Окна не пересекаются; объединение
их исходных строк должно точно восстановить всё сообщение. Молчаливая обрезка текста и
подстановка фиктивной записи при ошибке библиотеки запрещены. Схемы независимы: ограничений
между `dissatisfaction` и `correction` нет.

Помимо трёхклассового argmax, на calibration выбираются пороги `P(yes)` для recall 80% и 90%.
На test они применяются без изменений. `no` и `unclear` считаются не-yes в этом отдельном
бинарном диагностическом отборе; это не новая разметка и не изменение основных классов.

Сравнение проводится на тех же 1 353 test-входах; пять отсутствующих меток маскируются.
Полные исходные матрицы предыдущих моделей и GLiNER доступны в агрегированном JSON.
Этот публичный test уже исследовался раньше; пересечение с предобучением GLiNER неизвестно.
Метки Qwen не являются независимой человеческой оценкой правильности.

## Артефакты

В `runs/gliner25-decide-v1/`:

- `manifest.json`: хеш весов, входного исследования, политики и версии зависимостей;
- `scores.sqlite3`: возобновляемые результаты отдельных сообщений, без обращения к учителю;
- `selection.json`: четыре calibration-оценки и зафиксированный выбор;
- `evaluation.json`: test-метрики, confusion matrices, average precision и пороги;
- `test-predictions.jsonl`: локальные предсказания;
- `runtime.json`: CPU latency на тех же 100 входах, что и у предыдущих моделей;
- `report.md` и `complete.json`: итоговый отчёт и подтверждение завершения.

Отдельные этапы: `--stage score`, `--stage latency`, `--stage report`.
Последний пересобирает отчёт без повторного инференса. Другой протокол или новые данные
требуют нового `--out`. Старые результаты `feedback-v1` не перезаписываются.

Проверка адаптера через официальный `model.classify_text`:
`python scripts/check_gliner_api_parity.py`. Она использует короткие calibration-входы
и синтетические примеры, не test. Проверены 80 решений, расхождений нет.

График с матрицами и сравнением: `python scripts/plot_gliner_benchmark.py`
(нужен дополнительный пакет `.[experiments]`). Он использует только опубликованный
агрегированный JSON, без моделей и исходных сообщений.

Официальные источники:
[карточка модели](https://huggingface.co/fastino/GLiNER2.5-Decide),
[библиотека и API](https://github.com/fastino-ai/GLiNER2).
