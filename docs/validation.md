# Проверки реализации

## Трехклассовый студент, 14 сентября 2026

Проверены подготовка независимых сессий, Unicode-дубликаты и близкие шаблоны,
учет системного промпта в лимите входа, происхождение меток, отсутствие доступа
к test-целям при выборе модели, сохранение всех токенов длинного сообщения,
переносимая TF-IDF-голова, проверка checksum и вероятностная оценка частоты.
Отдельная проверка отклоняет смешение трехклассовых меток с прежней бинарной задачей.

Набор выполняется на Windows с Python 3.13 и в Linux-контейнере с Python 3.11.
Точные результаты и логи текущей серии сохранены в
`runs/sentiment-students-v1/verification.json`. CI также настроен для macOS,
но на этой машине macOS/MPS не запускались.

Дополнительно дообученный на Windows синтетический E5-артефакт перенесен в чистый
Linux-контейнер с PyTorch 2.8.0+cpu и теми же версиями Sentence Transformers/Transformers.
Checksum весов и идентификаторы входов совпали; максимальное отличие вероятностей
на трех синтетических сообщениях — 3,4236e-8. Протокол сохранен в
`runs/sentiment-students-v1/linux-encoder-parity.json` и соответствующем логе.

Реальный `intfloat/multilingual-e5-small`, revision
`614241f622f53c4eeff9890bdc4f31cfecc418b3`, дополнительно проверен на CPU:

- `scripts/verify_sentiment_encoder.py`: на семи синтетических коротких строках
  токенизация точно совпадает со стандартной, максимальное отличие эмбеддингов
  от `SentenceTransformer.encode` — около 1,5e-8. Длинный текст проходит через
  шесть окон с сохранением всей последовательности токенов.
- `scripts/smoke_sentiment_finetune.py`: синтетический прогон backward, сохранение
  safetensors, проверка checksum, повторная загрузка и совпадение вероятностей.
  Результат после исправления сериализации находится в
  `runs/student-finetune-synthetic-smoke-v2/smoke-result.json`.

Независимое сравнение обнаружило лишний токен пробела при раздельной токенизации
префикса и текста. Исправление `message-text-token-windows-v2` сделано до обучения
на исследовательских данных; эмбеддинги всех splits пересчитаны. Старый кэш
сохранен отдельно и не используется. Метки Qwen и состав выборок не менялись.

Эти проверки устанавливают корректность вычислений и сохранения модели.
Качество студента относительно Qwen оценивается отдельно в финальной серии;
синтетические показатели не являются исследовательским результатом.

Финальная проверка завершена 15 сентября: выбранный по calibration дообученный E5
дал 140/148 совпадений с Qwen, macro-F1 0,858. Экспортированная модель повторно
загружена через CLI и воспроизвела все 148 предсказаний с нулевым отличием
вероятностей. Проверены хеши данных/протокола и порядок выбора до test.
Протокол — `runs/sentiment-students-v1/final-verification.json`.
После временной остановки для GPU-обучения Qwen восстановлен; прежний API/model ID
проверен в `qwen-restored-health.json`.

## Предыдущие проверки ядра и судьи

Добавлен этап LLM-разметки: тесты импорта, изоляции исходных меток от запросов, стратифицированного
пилота, проверки JSON/evidence, retries, остановки на ошибке первого запроса, возобновления
SQLite-журнала, учета usage и происхождения llm_judge. На Windows исправлено явное закрытие
SQLite-соединения, необходимое для удаления/переноса файлов после завершения обработки.
Актуальный набор: 29 тестов ядра/судьи плюс один опциональный интеграционный тест энкодера.
Реальные измерения Qwen сохраняются в runs/qwen-pilot, отдельно от синтетических тестов.

Локальная среда: Windows, Python 3.13.0. Пакет установлен editable в проектное `.venv`.
Для ML-проверки окружение использует уже установленные на машине библиотеки:
NumPy 2.4.4, scikit-learn 1.6.1, Sentence Transformers 5.4.0, PyTorch 2.8.0+cu129.
Системное Python-окружение не изменялось. На другой машине создайте новое обычное venv;
проект не зависит от локальных абсолютных путей.

Результат 14 сентября 2026: 20 тестов ядра прошли, интеграционный тест отдельно прошел на CPU
и CUDA. Синтетическое CLI-демо и команда вероятностной выборки также выполнены. Код
отформатирован Black 24.10.0; проверка синтаксиса и `git diff --check` прошли.

Основной набор тестов проверяет причинность и видимость, доставочные дубли, пропавших родителей,
сохранение целевой реплики, независимые split-группы, неизвестные scores, различие shadow/cascade,
веса аудита, валидность evidence, статистические знаменатели и пути с кириллицей/пробелами.

Опциональный интеграционный тест проверяет настоящий замороженный энкодер, обучение головы,
предсказания, переполнение токенов и обнаружение пересечения групп обучения/test. Он использует
уже закэшированный `sentence-transformers/all-MiniLM-L6-v2` с ревизией
`c9745ed1d9f207416be6d2e6f8de32d1f16199bf` в offline-режиме. Это техническая проверка адаптера;
она не заменяет проверку рекомендованного E5 и не подтверждает качество на русском.

Запуск ядра:

```text
python -m unittest discover -s tests -v
```

В PowerShell запуск всей проверки с локальным HF-кэшем:

```powershell
$env:MB_TRACE_ML_TEST = '1'
$env:HF_HUB_OFFLINE = '1'
python -m unittest discover -s tests -v
```

В macOS/Linux для той же проверки:

```sh
MB_TRACE_ML_TEST=1 HF_HUB_OFFLINE=1 python -m unittest discover -s tests -v
```

По умолчанию интеграционный тест использует CPU. Для проверки CUDA дополнительно задайте
`MB_TRACE_ML_DEVICE=cuda`. Без `MB_TRACE_ML_TEST=1` тест пропускается и тяжелые библиотеки не
импортируются. Скачивать модель автоматически этот тест не будет.

CI настроен на Windows/macOS/Linux и Python 3.11/3.13. Локальный запуск на Windows не означает,
что удаленная матрица CI уже прошла; результаты остальных ОС будут доступны после ее запуска.
E5, MPS, реальный Memory Bank export и GLM-endpoint в этой итерации не проверялись.
