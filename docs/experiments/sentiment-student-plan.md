# Выполненный план: трехклассовый студент Qwen

Статус на 14 сентября 2026: пользователь принял
[результат Qwen](qwen-tuning-2026-09-14.md) как хорошую базовую версию.
Этот протокол выполнен 15 сентября 2026: массовая разметка, сравнение базовых моделей,
условное дообучение E5, финальная проверка, оба сценария отбора и переносимый артефакт.
[Результаты и ограничения](sentiment-students-2026-09-14.md).
Выбран дообученный E5; режим применения остается shadow. Ненадежность нормальных
интервалов при редких событиях зафиксирована как результат исследования.

## Зафиксированный учитель и задача

- Классы: NEGATIVE, NEUTRAL, POSITIVE; единица входа — одно пользовательское сообщение.
- Рубрика: `sentiment-content-valence-v2`, [точный текст](../../prompts/sentiment.txt).
- Judge fingerprint: `4bc20dc9ef8b6f15be2f478f2d55949c64a70ca0bd5a02981f748c531d854104`.
- Модель: `qwen38-ud-q4-k-xl`, thinking=low/enabled, temperature=0, max_tokens=4096.
- Принятый результат: 100/120 совпадений с источником, macro-F1 0,836, 119/120 валидных
  ответов. Технический пропуск входит в знаменатель. Проверка сбалансирована по классам.
- Обучающие цели — метки этой версии Qwen. Исходная разметка остается отдельным
  автоматическим ориентиром; спорные ответы не подменяются ее метками.
- Измеряем воспроизведение учителя и стоимость. NEGATIVE в этой рубрике не равен
  доказанной претензии к агенту; независимое качество распознавания эмоций неизвестно.

## 1. Подготовить данные и заморозить проверку

Сохранить существующее разбиение по сессиям, проверить пересечения нормализованных
текстов (Unicode NFKC, casefold, пробелы) и близких шаблонных дубликатов. Найденные
между splits совпадения устранить с документированным правилом; связанные примеры
не должны одновременно попасть в обучение и проверку. В исходном импорте уже найдено
184 уникальных точных текста с пересечением splits, поэтому старые файлы нельзя
использовать для сравнения студентов без этой подготовки.

Все ранее просмотренные сообщения и их сессии, включая holdout из 120 сообщений,
исключить из новой финальной проверки. Сохранить список ID, группы, правила отбора,
исключения и хеши в отдельном манифесте до обучения. Новый test внутри этого корпуса
проверяет воспроизведение учителя на оставленных сессиях; перенос на рабочие данные
потребует отдельного корпуса. Calibration используется для выбора модели и порогов.

Основную проверку проводить на не обогащенной по классам выборке; распределение классов
показывать явно. Отдельная диагностика редких классов не должна изменять оценку частот.
Правила обработки длинных входов зафиксировать до запуска; не обрезать их молча.
Выводы ограничивать объявленной областью допустимых входов, а исключения учитывать
в покрытии исходного корпуса.

## 2. Разметить фиксированным Qwen

Перед новой серией проверить доступность и идентичность deployment. Разметить допустимые
train/calibration/test с checkpoint и сохранением причин, ошибок, токенов и времени.
Существующие ответы переиспользовать только при совпадении фактического запроса
и judge fingerprint. Весам сервера не присваивать выдуманный SHA.

Для каждого входа сохранить исходную метку, метку учителя и их происхождение раздельно.
Учитель получает только разрешенный текст; источник и его объяснение не передаются.
Студент тоже получает только текст сообщения: объяснения и reasoning учителя
не становятся входными признаками. В обучение попадают только валидные метки;
пропуски остаются в отчете покрытия и не преобразуются в NEUTRAL.

## 3. Сравнить небольшие модели

Последовательность экспериментов:

1. Контроль: постоянный наиболее частый класс, определенный только по train.
2. TF-IDF по словам и символам + трехклассовая логистическая регрессия.
3. Замороженный компактный многоязычный энкодер + такая же трехклассовая голова.
4. При перспективных результатах и заметном остаточном разрыве — дообучение энкодера.

Ранее выбранный в проекте кандидат энкодера — `intfloat/multilingual-e5-small`.
Перед реальным запуском зафиксировать checkpoint revision и способ подачи текста.
Сначала расширить нынешний бинарный интерфейс обучения для трех классов, не смешивая
старые yes/no/unclear с sentiment. Все варианты используют одинаковые входы и splits.
Гиперпараметры, балансировку и калибровку выбирать без просмотра финальных результатов.

Построить кривую обучения на вложенных подвыборках train, например 500, 2 000 и всех
доступных сообщениях. Сохранять группы и seed; фактические размеры и состав классов
отразить в отчете. Это проверит пользу дополнительной разметки и необходимость
дообучения большой модели вместо предположения, что большее железо само улучшит результат.

## 4. Оценить оба пользовательских сценария

**Высокая полнота NEGATIVE.** На calibration построить зависимость полноты от доли
сообщений, направляемых к Qwen, и полной стоимости. Для нескольких заранее выбранных
политик измерить recall/precision относительно Qwen, число его вызовов и затраты
студента. Для группировки по сессиям отдельно показать полноту сообщений и сессий;
псевдометки тональности не превращать в доказанные ошибки агента.

**Оценка доли NEGATIVE.** Сравнить полную разметку учителем, случайную выборочную
проверку и фильтр с вероятностным аудитом пропущенных сообщений или сессий.
Вероятности включения сохранять, учитывать при оценке частоты и неопределенности.
Не оценивать частоту по одному только набору срабатываний. Целевая величина здесь —
доля NEGATIVE по рубрике Qwen в допустимом потоке, а не неизвестная доля реальных претензий.

Общий отчет: согласие с Qwen, macro-F1, precision/recall/F1 каждого класса, confusion
matrix, покрытие, ошибки, p50/p95 latency, throughput, память и доля вызовов учителя.
Интервалы учитывать по сессиям; при выборочном аудите — с учетом дизайна отбора.
Одинаковые сохраненные ответы Qwen позволяют сравнить политики без повторной генерации.
Финальную проверку выполнить после фиксации кандидата и порогов; ее результаты
не использовать для последующего подбора в этой же серии.

Python и переносимые артефакты остаются основой. CPU — доступный базовый режим;
MPS/CUDA и размер батча задаются параметрами. Производительность на каждой машине
измеряется отдельно. Сильные GPU пригодятся для эмбеддингов и возможного дообучения;
обязательный GPU-сервис для студента на этом этапе не нужен.

Практический результат этапа — таблица качества и стоимости, сохраненная модель
и воспроизводимый запуск, по которым можно выбрать студента или оставить Qwen
на всех сообщениях. Начальный режим применения фильтра — shadow.
