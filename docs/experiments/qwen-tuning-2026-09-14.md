# Подбор рубрики Qwen — 14 сентября 2026

**Статус: результат принят пользователем 14 сентября 2026 как хорошая базовая версия
для разметки и обучения студентов.** Подбор рубрики на этом этапе завершен.
Промпт, конфигурация и результаты ниже зафиксированы; ошибки исходного датасета
не являются основанием подгонять учителя до полного совпадения.
[Следующий этап](sentiment-student-plan.md) — обучение и оценка небольших моделей.

На отдельной проверочной выборке **совпадение выросло с 45,0% до 83,3%**:
54 → 100 совпадений из 120. Расхождение уменьшилось с **55,0% до 16,7%**.
Выбранная конфигурация уже подключена в `configs/judge.local.json`.

Это лучший из проверенных вариантов по development-выборке. Глобальный минимум расхождения
не установлен. Измерено воспроизведение автоматической разметки датасета, а не человеческая
оценка качества тональности.

## Что изменилось

Текущая рубрика — [prompts/sentiment.txt](../../prompts/sentiment.txt), версия
`sentiment-content-valence-v2`. Оценивается тональность всего содержания, включая описанную
проблему или желаемый результат. Для негативной метки не требуются сильная эмоция или доказанное
недовольство предыдущим действием агента. Для позитивной учитываются удовлетворенность,
одобрение, оптимизм и привлекательное описание желаемого результата. Команда не отменяет
оценку в том же сообщении.

Модель по-прежнему получает одно пользовательское сообщение, без истории, исходной метки,
исходного объяснения или агрегатов сессии. Ответ содержит только три класса
NEGATIVE / NEUTRAL / POSITIVE и короткое объяснение. В выбранном промпте нет размеченных примеров.

Thinking включен на уровне запроса: `reasoning_effort=low`,
`chat_template_kwargs.enable_thinking=true`, `max_tokens=4096`, temperature=0,
concurrency=1, timeout=60 секунд, retries=0. Сервер действительно возвращал отдельное поле
reasoning; это не предположение по названию параметра. Один неуспешный запрос позднее повторен
через `--retry-errors`, с сохранением обеих попыток.

Модель — тот же served ID `qwen38-ud-q4-k-xl`, API сообщает 27 320 697 856 параметров,
Q4 GGUF и контекст 262 144. Доступность и ID проверены перед экспериментом.
Хеш весов сервер не предоставил. Фактический judge fingerprint:
`4bc20dc9ef8b6f15be2f478f2d55949c64a70ca0bd5a02981f748c531d854104`.

## Как подбирали

Датасет: `davanstrien/agent-trace-sentiment`, revision
`434c8d7b267672cc4638bb5a80fb0da13d18d76d`.

- Development: 75 сообщений из уже просмотренного пилота, по 25 каждого исходного класса.
- Holdout: заранее зафиксированные 120 сообщений из split=test, по 40 каждого класса,
  из 120 разных сессий. Сессии не пересекаются с development.
- Из holdout исключены тексты, повторяющие любой текст старого пилота после Unicode NFKC,
  casefold и нормализации пробелов. Внутри каждой выборки тексты тоже уникальны.
- Входы длиннее 14 000 символов не участвовали в этом отборе; текст выбранных входов не обрезался.
- Кандидаты выбирались по согласию на development; при равенстве — по macro-F1, затем времени.
  Требовалось получить ответы на всех 75 входах.
- Победитель зафиксирован в `selection.json` до запуска обеих holdout-конфигураций.
  После результатов holdout промпт и выбор кандидата не менялись.

| Вариант | Совпадение на development | Macro-F1 |
|---|---:|---:|
| Прежний трёхклассовый промпт, сохранённые ответы | 45,3% | — |
| Минимальная инструкция | 72,0% | 0,721 |
| Подробные правила с приоритетом эмоций | 68,0% | 0,676 |
| Более широкая трактовка тональности диалога | 70,7% | 0,707 |

| Тональность всего содержания + thinking | **85,3%** | **0,851** |

Девять примеров для отдельного few-shot кандидата выбраны по лексическим прототипам
из train, по три каждого исходного класса, из разных сессий. Они не повторяют тексты
calibration/test. Их источник и алгоритм отбора сохранены в `fewshot-provenance.json`.
Новых человеческих меток не создавалось.

Для thinking сначала использовались 12 заранее выбранных development-сообщений:
8/12 совпадений без thinking и 10/12 с thinking. После этого кандидат проверен на всех 75;
12 уже полученных идентичных запросов использованы из checkpoint, без повторной генерации.
Прибавка thinking на development — два совпадения, 62 → 64 из 75. Основная наблюдаемая
прибавка связана с рубрикой. Отдельный эффект thinking на holdout этим дизайном не измерен.

## Итог на других сессиях

Все метрики в таблице учитывают 120 входов; отсутствие ответа считается несовпадением

52 решения стали совпадать с источником, 6 перестали. Прирост согласия — **38,3 п.п.**
Стратифицированный парный bootstrap по сессиям дает 95% интервал прироста **30,8…45,8 п.п.**
(10 000 повторов, seed=42). Метрики независимо сверены с scikit-learn.

## Качественный разбор расхождений после проверки

Просмотрены все 19 расхождений с валидной меткой: полный текст сообщения, объяснение
исходного разметчика из Parquet и объяснение Qwen. Отдельно остается один технический
сбой без JSON. Это анализ ассистентом, а не независимая человеческая разметка;
новые эталонные метки не создавались, исходные ответы и числовые метрики не менялись.

| Строка исходного Parquet | Содержание | Источник / Qwen | Оценка при разборе |
|---|---|---|---|
| 5344 | Просьба найти компонент | NEGATIVE / NEUTRAL | NEUTRAL убедительнее: исходное объяснение приписывает агенту предыдущую неудачу, которой в тексте нет. |
| 3248 | Просьба строго проверить переписывание runtime | NEGATIVE / NEUTRAL | NEUTRAL убедительнее: источник утверждает наличие архитектурных поломок, хотя пользователь просит их проверить. |
| 1174 | Вежливая просьба пересмотреть UI/UX | POSITIVE / NEUTRAL | NEUTRAL убедительнее: конструктивность запроса сама по себе не подтверждает воодушевление. |
| 3173 | Вопрос, встречается ли проблема в другой игре | NEUTRAL / NEGATIVE | NEUTRAL убедительнее при оценке отношения пользователя; Qwen реагирует на упоминание проблемы. |
| 5973 | Разговорная просьба удалить код с ругательством | NEUTRAL / NEGATIVE | Скорее NEUTRAL: привычная манера речи разработчика не обязательно выражает раздражение. |

У источника повторяется приписывание эмоций: конструктивная задача превращается
в удовлетворение, обычная команда — в раздражение. У Qwen встречается избыточный NEGATIVE
на технических вопросах, описании дефектов и разговорной лексике. Этому способствует
выбранная нами широкая рубрика тональности содержания. Часть расхождений отражает
различие определений, а не однозначную ошибку одной модели. Истории диалога не было
у обоих разметчиков; предполагаемые предыдущие события нельзя считать доказательством.

В этой подборке исходная разметка чаще выглядела сомнительной, но разбор расхождений
не измеряет частоту ошибок во всем корпусе и не исключает общие ошибки при совпадении.
Принятие результата означает готовность использовать версионированного учителя
для следующего исследовательского этапа; это не подтверждение production-качества
детектора недовольства агентом.

## Ограничения и реализация

Подбор оптимизирует совпадение с автоматическим источником. Часть спорных исходных меток может
быть воспроизведена вместе с его ошибками. Выборка сбалансирована, очищена от повторов и
содержит по одному сообщению на сессию; ее доли не описывают естественный поток. Корпус ранее
использовался для разведочного анализа: это отдельная проверка текущего подбора, не независимая
оценка production-качества. История сообщений, другая квантизация и другие модели не сравнивались.

Код поддерживает отдельный файл промпта, обязательную версию, fingerprint фактического текста,
точный экспорт `judge-plan --config`, прежние конфигурации и возобновляемые вызовы.
35 автоматических тестов прошли; один дополнительный ML-тест пропущен. Black проверяет весь
Python-код. Обучение студента и массовая разметка остальных splits не выполнялись.

Основные артефакты находятся в `runs/sentiment-tuning-v1/`:

- `design.json`, `development.jsonl`, `holdout.jsonl`: зафиксированный дизайн и входы.
- `screening-ranking.json`, `selection.json`: подбор и выбранная версия до holdout.
- `configs/`: точные конфигурации всех кандидатов.
- `holdout-baseline/`, `holdout-winner/`: ответы, метки, ошибки и числовые отчеты.
- `holdout-comparison.json`, `report.md`: сравнение на всех входах и парный bootstrap.
- `holdout-changed-predictions.jsonl`: изменившиеся решения с текстами сообщений.

Скрипты в `scripts/` готовят выборки, запускают сохраненные кандидаты и фиксируют победителя.
Для повторного выполнения уже проведенного holdout без новых API-вызовов:

```text
python scripts/run_sentiment_candidates.py baseline winner --inputs holdout --prefix holdout-
python scripts/summarize_sentiment_tuning.py report
```

Текущий промпт и пример конфигурации находятся в репозитории. Локальные данные, подробные
журналы и ключ остаются исключенными из Git. Прежняя локальная конфигурация сохранена
в `configs/judge.before-tuning.local.json`.
