# Qwen: только NEGATIVE / NEUTRAL / POSITIVE — 14 сентября 2026

Прогон завершен: **147 из 299 меток совпали с источником (49,2%)**.
В предыдущем эксперименте совпали 172 из тех же 299 (57,5%). Изменение — **−8,4 п.п.**
Текущая конфигурация размечает только тональность; оценка явной претензии не запрашивается.

## Методика

- Тот же `davanstrien/agent-trace-sentiment`, revision
  `434c8d7b267672cc4638bb5a80fb0da13d18d76d`.
- Те же 300 входов из session-grouped calibration, по 100 каждого исходного класса, seed 42.
  Состав успешно оцененных входов в двух прогонах совпадает точно.
- На входе одно пользовательское сообщение без истории ответов агента. Исходные метки,
  объяснения и агрегаты сессий скрыты.
- API model ID `qwen38-ud-q4-k-xl`, 27 320 697 856 параметров, Q4 GGUF, llama.cpp.
  Доступность и ID проверены перед запуском. Хеш весов сервер не предоставил.
- Настройки запросов прежние: temperature=0, reasoning_effort=none, max_tokens=768,
  max_input_chars=20000, concurrency=1. Один вызов на сообщение; повторяемость не измеряется.
- Ответ модели: JSON `{label, reason}`, где label — один из трех классов.
  В нормализованных данных это поле называется `sentiment_label`.
- Рубрика `sentiment-domain-rules-v1` — смысловая адаптация опубликованных
  [правил автора датасета](https://danielvanstrien.xyz/posts/2026/agent-sentiment/#how-we-labelled-the-messages),
  без дополнительной бинарной задачи и без few-shot примеров. Это не дословное воспроизведение
  исходного промпта. По статье автора, исходный разметчик — Qwen3-30B-A3B-Instruct-2507.

Правила: брань как часть обычной инструкции, короткие команды/согласия и сообщения о статусе
считаются нейтральными; недовольство качеством ответа негативно; удовлетворенность или
воодушевление прогрессом позитивны. Точный использованный текст сохранен в `run.json`.

На просмотренных примерах видно чрезмерно широкое применение правила о нейтральной брани:

- Строка 6280: резкое требование откатить изменения агента. Источник и прежний промпт —
  NEGATIVE; новый ответ — NEUTRAL, с объяснением через обычный сленг и команду отката.
- Строка 7856: грубый упрек в адрес собеседника при исправлении команды установки.
  Источник и прежний промпт — NEGATIVE; новый ответ — NEUTRAL, с объяснением через
  обычную команду и разговорный сленг.

Это качественный разбор отдельных ответов, не дополнительная эталонная разметка.
Новый промпт усилил склонность модели к нейтральному классу. Результат не подтверждает
гипотезу, что переход к одной задаче с этой рубрикой повысит согласие. Одновременно поменялись
текст промпта и схема ответа, поэтому отдельно эффект удаления бинарного поля здесь не измерен.
Влияние thinking и квантизации также не измерялось.

## Выполнение и проверки

- 299 сообщений получили метки; строка 2312 (939 251 символ) пропущена по лимиту, без обрезки.
- Два ответа содержали корректный JSON внутри Markdown-блока. Первоначальная строгая
  проверка отклонила их. Парсер расширен только для одиночной оболочки вокруг всего ответа,
  с прежней проверкой класса и полей. Произвольный текст вокруг JSON не принимается.
- Повторены только эти два неуспешных вызова; прежние попытки и сырые ответы сохранены.
  В двух случаях зафиксировано `response_wrapper=json_fence`. Промпт и параметры не менялись.
- Всего 305 попыток API с учетом повторов; окончательных ошибок нет. Сумма времени попыток
  390,8 с, латентность успешного запроса p50/p95 — 1,04/2,21 с.
- Usage сервера: 86 945 prompt tokens, 12 239 completion tokens, 99 184 total tokens.
- 33 автоматических теста прошли, один дополнительный ML-тест пропущен. Проверены новый
  формат, отсутствие исходной разметки во входе, восстановление из checkpoint, несовпадающие
  повторы, обработка JSON-оболочки и прежний режим. Black проверяет весь код.

Согласие с автоматическими метками не равно точности относительно независимого эталона.
Пилот сбалансирован по классам; его доли не описывают естественный поток сообщений.
Обучение моделей и разметка остальных splits этим прогоном не выполнялись.
