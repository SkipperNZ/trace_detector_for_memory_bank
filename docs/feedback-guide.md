# Разметка недовольства и исправлений

Исследование использует две независимые задачи с классами `no / yes / unclear`:

- `dissatisfaction`: явная претензия, раздражение или разочарование работой агента.
- `correction`: указание на ошибку, пропуск или нарушенное требование в предыдущей работе агента. Спокойное исправление тоже считается.

Это новая рубрика, отдельная от тональности NEGATIVE / NEUTRAL / POSITIVE. Полный промпт:
[`prompts/feedback.txt`](../prompts/feedback.txt). Каждая положительная метка требует точной
цитаты из целевой реплики. Причины `wrong_result`, `ignored_requirement`, `repeated_mistake`,
`unnecessary_action`, `reported_loop`, `reported_backtracking` могут пересекаться.
Последние две — сообщения пользователя о поведении агента; фактические циклы и откаты
нужно проверять отдельно по событиям. Студенты обучаются только на двух основных задачах.

## Подготовка окружения

Python 3.11–3.13, Windows / macOS / Linux. Из корня проекта:

```text
python -m venv .venv
python -m pip install -e ".[ml,experiments]"
python scripts/cache_feedback_encoders.py
```

Команды `python` выполняйте интерпретатором созданной среды: `.venv/Scripts/python.exe`
на Windows, `.venv/bin/python` на macOS/Linux, либо активируйте среду. CUDA-версию PyTorch
устанавливают под драйвер рабочей машины. CPU поддерживается; на macOS доступен `--device mps`.
Дообучение большого BGE на MPS не проверялось; при недостатке памяти используйте CPU или CUDA.
В GPU-обучении применяется bf16, если устройство его поддерживает, иначе float32.

Для изолированного контура заранее перенесите исходники, зависимости и `artifacts/hf`.
Скрипт загрузки обращается только к публичным весам Hugging Face. Основной запуск использует
локальные веса и не скачивает модели. Окно 512 токенов не обрезает текст: длинные входы
разбиваются на окна с взвешенным усреднением. Потребность обучения в памяти растёт с длиной входа.

Скопируйте `configs/judge-feedback.example.json` в `configs/judge-feedback.local.json`.
Укажите внутренний OpenAI-совместимый URL, точное имя модели и deployment_id.
Ключ передайте через переменную `MB_JUDGE_API_KEY` либо `api_key_file` в локальном конфиге.
Путь к файлу ключа разрешается относительно конфигурации. Секрет не передаётся в аргументах CLI.
При замене весов/квантовки меняйте deployment_id. Конфигурация и промпт входят в версию разметчика.

## Формат данных

Минимальный JSONL — одна пользовательская реплика на строку:

```json
{"tenant_id":"company","session_id":"session-1","message_id":"user-3","text":"В твоём патче снова пропущена проверка входа. Исправь её."}
```

В этом формате предыдущая переписка отсутствует, что явно сообщается учителю.
Для корпоративных трейсов предпочтительнее подготовленный causal-prefix формат из
[`docs/data-contract.md`](data-contract.md). Нужны `tenant_id`, `trace_id`, `branch_id`,
`group_id`, `input_id`, `target_event_id`, `context_scope`, `context_status`,
`history_available` и `context`: список `{event_id, role, text}` в причинном порядке.
Контекст должен заканчиваться целевой пользовательской репликой. Включайте только видимые
предыдущие сообщения и результаты инструментов; будущие события запрещены.
Существующий подготовщик `mb-trace prepare` строит такие префиксы из событий.
Студент получает тот же видимый контекст, сериализованный вместе с ролями и целевым ID.

Tenant и session ID должны быть стабильны. Train/calibration/test разделяются по сессиям;
перед обучением проверяются также точные и близкие дубликаты. Предоставленный `split`
из допустимых значений сохраняется, но пересечения сессий/дубликатов не допускаются.

## Автономный запуск

```text
python scripts/run_feedback_study.py --source data/company-inputs.jsonl --base runs/company-feedback-v1 --config configs/judge-feedback.local.json --model-output artifacts/company-feedback-v1 --device cuda
```

Порядок: фиксируем данные и политику → пилот 256 → весь корпус → TF-IDF → E5 frozen/finetuned →
BGE-M3 frozen/finetuned → выбор на calibration → однократная test-оценка → отчёт и экспорт.
Две головы используют общий бэкбон. Сетка и режимы обучения заданы в `configs/feedback-study.json`.
Первый пилот проверяет валидность JSON/цитат и измеряет время; это не проверка смысловой
точности учителя. Он автоматически разрешает полный запуск при доле технически корректных
ответов ≥95%. При техническом провале скрипт останавливается, сохраняя журнал для исправления.

`pilot-gate.json` содержит оценку оставшегося времени с запасом. Этапами управляет Python;
проверки статуса со стороны LLM не нужны. `progress.json` и отдельные `.log` содержат состояние.
Повторный запуск той же команды продолжает завершённые этапы и использует SQLite-кеш запросов.
После изменения данных, промпта или политики нужен новый `--base`.
Для отдельного пилота добавьте `--stop-after-pilot`, затем уберите его для продолжения.

Если локальный Qwen делит GPU со студентами, поддержан необязательный параметр
`--qwen-compose-dir PATH`. Он применим к имеющемуся менеджеру Qwen с Docker Compose
профилем `llama` и сервисом `qwen38-llama`: скрипт останавливает этот сервис перед CUDA-обучением,
восстанавливает в `finally` и проверяет API. Без параметра скрипт не управляет сервером.
При аварийном выключении машины запустите ту же команду, чтобы восстановить прерванное состояние.

## Результаты и перенос модели

В каталоге запуска сохраняются:

- `census.json`: доли признаков по всему входному корпусу, пересечения и причины;
- `labels.jsonl`: автоматические метки и цитаты; `teacher/calls.sqlite3`: журнал запросов;
- `selection.json`: модель выбрана по calibration до test;
- `evaluation.json`: согласие с Qwen, confusion matrices, support, macro-F1, precision/recall/F1
  для каждого класса, bootstrap по сессиям и CPU latency;
- `report.md`: итоговая сводка; `export-verification.json`: проверка повторной загрузки модели.

Неразмеченные по технической причине сообщения не заменяются классом `no`. Доли по всему
корпусу учитывают исходные повторы; очистка обучающей выборки не меняет знаменатель переписи.
`unclear` — смысловая неопределённость учителя, отдельная от ошибки исполнения.
Это согласие с автоматическим учителем, а не независимая оценка объективной точности.

Каталог `--model-output` содержит выбранную модель, веса, токенизатор, две головы и конфигурацию.
Его можно перенести вместе с Python-пакетом без Hugging Face кеша. Запуск без Qwen:

```text
python scripts/predict_feedback.py data/new-inputs.jsonl --model-dir artifacts/company-feedback-v1 --out runs/new-predictions.jsonl --device cpu
```

На каждую задачу возвращаются класс и вероятности трёх классов. Начальный режим — shadow.
Порог фильтрации и вероятность аудита для оценки долей подбираются отдельно на корпоративной
calibration-выборке. Для обученных здесь моделей test не используется повторно для подбора.
Данные, метки, логи, ключи и веса исключены из Git. В публичный репозиторий публикуются код,
примеры конфигурации и проверенные агрегированные отчёты.
