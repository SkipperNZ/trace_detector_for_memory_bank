# Memory Bank: исследование детекторов трейсов

Новый этап: **[разметка недовольства и исправлений](docs/feedback-guide.md)** — два независимых
признака `dissatisfaction` / `correction`, каждый `no / yes / unclear`. Автономный Python-пайплайн
размечает данные локальным Qwen, сравнивает TF-IDF, E5 и BGE-M3 и экспортирует выбранную модель.
Код и формат входа подготовлены для переноса в корпоративный контур.

Python-пакет для Windows, macOS и Linux. Текущий эксперимент: берем публичные пользовательские
сообщения, размечаем собственным Qwen через **LLM-as-a-judge** в NEGATIVE / NEUTRAL / POSITIVE,
проверяем согласие с исходными автоматическими метками,
затем используем зафиксированные метки учителя для обучения небольших моделей.
Человеческая разметка в текущем плане не требуется.

**[Принятая базовая версия Qwen — 14 сентября 2026](docs/experiments/qwen-tuning-2026-09-14.md)**:
на 120 других сессиях совпадение с исходными метками выросло с **45,0% до 83,3%**,
macro-F1 — с 0,378 до 0,836. Победитель выбран на 75 development-сообщениях до проверки.
Один вход остался без финального JSON и учтен как несовпадение. Текущая конфигурация
использует рубрику тональности всего содержания и thinking с бюджетом 4096 токенов.
Пользователь принял результат как достаточный для перехода к обучению студентов.
Рубрика и параметры зафиксированы; дальнейший подбор под исходные метки завершен.
83,3% — согласие двух автоматических разметчиков; разбор выявил ошибки обеих сторон.
**[Результаты сравнения студентов — 15 сентября 2026](docs/experiments/sentiment-students-2026-09-14.md)**:
размечены 6 857 из 6 873 допустимых сообщений. По calibration выбран дообученный E5;
на отдельном test — **140/148 совпадений с Qwen (94,6%)**, macro-F1 **0,858**.
Медиана предсказания на CPU — 6,7 мс. В test всего 11 NEGATIVE и 9 POSITIVE,
поэтому выводы о редких классах ограничены. Модель сохранена в
`artifacts/sentiment-student-v1/`, исходный режим — shadow.
Оба сценария исследованы: фильтрация сокращает вызовы учителя, а для оценки доли
нужен вероятностный аудит; обычные нормальные интервалы оказались ненадежными на малом test.
[Выполненный план](docs/experiments/sentiment-student-plan.md).

## Данные и пилот

Подключен [davanstrien/agent-trace-sentiment](https://huggingface.co/datasets/davanstrien/agent-trace-sentiment),
revision `434c8d7b267672cc4638bb5a80fb0da13d18d76d`:

| Исходная автоматическая метка | Сообщений |
|---|---:|
| NEGATIVE | 1 254 |
| NEUTRAL | 6 913 |
| POSITIVE | 782 |
| Всего | 8 949 |

В импорте 1 589 сессий и 33 источника. Первоначальное разбиение по сессиям: 6 218 train, 1 377 calibration,
1 354 test. Пилот — 300 сообщений из calibration, по 100 каждого класса. Это обогащенная
выборка для диагностики классов, не оценка естественной частоты проблем.

Для сравнения студентов зафиксирована отдельная очищенная выборка из **6 873 сообщений**:
5 366 train, 1 359 calibration и 148 test. Сессии и компоненты дубликатов между частями
не пересекаются. Из test исключены ранее просмотренные сессии и похожие тексты;
его 148 сообщений относятся к 92 сессиям. Правила и исключения сохранены в
`runs/sentiment-students-v1/data/design.json`. Эти числа обозначают допустимые входы;
число успешных меток учителя показывается отдельно.

Таблица содержит отдельные пользовательские сообщения, поэтому эксперимент явно обозначен
`message_only`. История ответов агента не выдумывается. `sentiment_label`, исходное объяснение
метки и агрегаты будущей сессии **не передаются** судье или энкодеру.

## Установка

Нужен Python 3.11+. Для чистого окружения:

```text
python -m venv .venv
```

Windows PowerShell: `.venv\Scripts\Activate.ps1`; macOS/Linux: `source .venv/bin/activate`.
На системах с командой `python3` используйте ее при создании окружения.

```text
python -m pip install -e ".[dataset]"
python -m unittest discover -s tests -v
```

Ядро и API-клиент используют стандартную библиотеку; `dataset` добавляет чтение Parquet.
Обучение дополнительно требует `python -m pip install -e ".[ml]"`. `mb-trace` можно заменить
на `python -m memory_trace`, если скрипт не доступен в PATH.

## Воспроизводимый запуск судьи

```text
mb-trace fetch-sentiment --out data/agent-trace-sentiment
mb-trace import-sentiment data/agent-trace-sentiment/train.parquet --out runs/sentiment
```

Первые два шага уже выполнены на текущей машине. Манифест сохраняет SHA исходного Parquet,
ревизию датасета, классы, split и дизайн отбора. `judge-plan` позволяет посмотреть точные
system/user messages без сетевых запросов.

Для проверки пользовательской рубрики используйте `judge-plan ... --config configs/judge.local.json`.
Конфигурация поддерживает `prompt_file` (путь относительно файла конфигурации) и обязательный
`prompt_version`; альтернативно текст можно передать в `system_prompt`. Точное содержимое,
а не путь к файлу, входит в fingerprint и сохраняется в манифесте запуска.

Создайте `configs/judge.local.json` по [примеру](configs/judge.example.json): укажите реальный
base URL, model ID и идентификатор deployment. `task: "sentiment"` включает только три класса
тональности. На текущей машине подключение уже настроено.
Ключ берется из `MB_JUDGE_API_KEY` либо из `api_key_file` в конфигурации; относительный путь
считается от папки конфигурации. Файлы `configs/*.local.json` и `configs/*.local.txt` исключены
из Git. Сам ключ не сохраняется в манифестах или запросах.

```text
mb-trace judge-plan runs/sentiment/pilot.jsonl --config configs/judge.local.json --out runs/sentiment/judge-requests.jsonl
mb-trace judge runs/sentiment/pilot.jsonl --config configs/judge.local.json --out runs/qwen-current-pilot --repeats 1
mb-trace judge-report runs/sentiment/pilot.jsonl --calls runs/qwen-current-pilot/calls.jsonl --source-labels runs/sentiment/source_labels.jsonl --out runs/qwen-current-pilot/comparison --repeats 1
```

Повтор той же команды `judge` продолжает незавершенный запуск и использует SQLite-checkpoint.
`--retry-errors` повторяет ошибочные вызовы, сохраняя предыдущие попытки. При изменении модели,
рубрики, параметров или состава входов нужен новый `--out`. Первым идет пробный запрос;
если он завершается ошибкой, остальные запросы не отправляются.

Текущая конфигурация использует thinking: `reasoning_effort: "low"` и
`chat_template_kwargs: {"enable_thinking": true}`, с лимитом 4096 выходных токенов.
Наличие reasoning подтверждено ответами сервера. Режим задается на уровне запроса;
глобальные настройки сервера не меняются. Прежние прогоны использовали
`reasoning_effort: "none"` и 768 токенов. Рабочая конфигурация отправляет один запрос
одновременно, поскольку сервер сообщает один slot.

## Что именно оценивает судья

Текущий ответ API содержит только `label: NEGATIVE | NEUTRAL | POSITIVE` и `reason`.
При сохранении класс называется `sentiment_label`; бинарная оценка претензии не создается.
Текст текущей рубрики находится в [prompts/sentiment.txt](prompts/sentiment.txt).
Она оценивает тональность всего содержания, включая описанную проблему или желаемый результат,
а не только отношение к ассистенту. Учитываются спокойная критика, сомнение и негативные
описания дефектов, а также похвала и позитивные описания желаемого результата. Обычные команды
без оценки нейтральны. Команда не отменяет эмоциональную оценку в том же сообщении.
Рубрика выбрана по совпадению с автоматической разметкой development-выборки;
это не дословное воспроизведение промпта автора. Точная версия и текст сохраняются в `run.json`.

Для сравнения используется первый ответ на каждом входе. В текущих экспериментах выполняется
один вызов: повторяемость при temperature=0 не измеряется. Если явно запрошено
несколько повторов и классы разошлись, вход попадает в `unresolved.jsonl`; четвертый класс
не вводится. Ошибочные и слишком длинные входы тоже остаются без метки.

Старый режим `task: "sentiment_and_complaint"` сохранен для воспроизведения прежних экспериментов;
конфигурации без `task` используют его ради совместимости. Для `judge-plan` режим задается
через `--task` (по умолчанию `sentiment`).

| Файл в папке запуска | Содержание |
|---|---|
| run.json | Рубрика, prompt version, модель, параметры, fingerprint |
| calls.sqlite3 | Возобновляемый журнал вызовов |
| calls.jsonl | Все попытки, сырые ответы, ошибки, фактические usage и elapsed time |
| labels.jsonl | Успешно полученные метки с label_source=llm_judge |
| labeled_examples.jsonl | Входы, соответствующие экспортированным меткам |
| unresolved.jsonl | Входы, для которых разметка не получена полностью |
| comparison/report.json | Согласие с исходными метками и повторяемость |
| comparison/disagreements.jsonl | Примеры расхождений для анализа |

Отчет показывает confusion matrix, class-wise precision/recall/F1 относительно исходных
автоматических меток, долю успешных ответов и согласованность повторов. Пропуски отдельно
учтены в показателе на всех входах. Два одинаковых вызова при temperature=0 проверяют
повторяемость API; они не устанавливают правильность ответа.

## Обучение после проверки судьи

План подготовки, разметки и сравнения трехклассовых студентов выполнен.
Получены 5 353 валидные train-метки, 1 356 calibration-меток и все 148 test-меток.
Шестнадцать технических пропусков после повторных запросов остаются без класса.
Сравнены постоянный класс, TF-IDF, замороженный E5 и дообученный E5;
модель и пороги зафиксированы до финальной проверки.
Для трех классов реализованы отдельные `train-sentiment` и `predict-sentiment`.
Поддерживаются TF-IDF по словам/символам, замороженный E5 с логистической головой
и эксперименты с дообучением E5 или BGE-M3. Прежняя команда `train` остается бинарной.
[Инструкция по запуску и переносу студента](docs/sentiment-student-guide.md) содержит
Python API для новых сообщений, CLI, зависимости и порядок воспроизведения.

Для BGE-M3 предусмотрен отдельный [протокол](configs/student-study-bge-m3.json)
и `scripts/run_backbone_study.py`: он повторно использует готовые метки Qwen,
проверяет замороженный/дообученный бэкбон и сохраняет результат отдельно от E5.
Для чистого сравнения используется то же окно 512 токенов с сохранением полного
текста; штатный префикс и пулинг выбираются по модели. В CLI артефакт сам задаёт
эти параметры. [Отчёт BGE-M3](docs/experiments/sentiment-bge-m3-2026-09-15.md).

Для энкодера нужно фиксировать полную ревизию checkpoint. По умолчанию кандидат —
`intfloat/multilingual-e5-small`, префикс `query: `. CPU/MPS/CUDA выбираются через `--device`;
мощная GPU ускоряет батчи, но не требуется для работы ядра. Сборку PyTorch выбирайте под машину
через [официальный selector](https://pytorch.org/get-started/locally/).

Голова хранит происхождение меток, версии судьи, хеш меток/входов, группы обучения и окружение.
`train`, `evaluate`, `prevalence` в CLI по умолчанию ожидают `llm_judge`; для прежнего ручного
протокола можно явно указать `--label-source human`.

В исходном импорте обнаружены 184 уникальных точных текста, встречающихся в разных splits.
В новой выборке студентов устранены пересечения точных и близких дубликатов.
Ее test проверяет перенос на оставленные сессии этого публичного корпуса;
для проверки production-качества потребуется независимый рабочий корпус.

## Другие функции и ограничения

Для собственного журнала событий доступны `prepare`, `route`, `sample`, `evaluate`, `prevalence`.
По умолчанию маршрутизация работает в shadow. `demo` использует синтетические примеры только
для проверки программной логики.

Согласие с Qwen будет мерой воспроизведения учителя. Без независимого эталона оно не является
доказательством качества распознавания пользовательского недовольства. Корпус преимущественно
английский; сам этот прогон не подтверждает качество на русском или причинный эффект Memory Bank.
